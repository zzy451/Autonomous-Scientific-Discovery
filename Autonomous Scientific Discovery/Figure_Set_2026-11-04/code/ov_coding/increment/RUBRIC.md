# 评判 Rubric：问题开放度 O · 验证强度 V · 系统自主性 L

版本：2026-11-04。适用：Agent for Science 核心库 662 篇（2026-11-01 快照）。
**依据以提案为准**：赵哲《From Computable Tasks to Open Science: A Chronicle of AI Problem Solving》§2(1)，以及提案“02 · 意义”图：

- 纵轴“问题开放度”O1 规则世界 → O2 既定基准 → O3 新实例 → O4 需物理检验 → O5 开放数学 → O6 开放科学；“开放度：从问题陈述读出”。
- 横轴“验证强度”V0 声明 → V1 → V2 → V3 → V4 证明/复现；“形式化证明、物理实验或第三方复现，才算强验证”。
- 第三条轴“系统自主性 L0–L3：保留，但不再代替‘解决程度’”。

提案只规定了两端与强验证的门槛；中间等级的判据、边界规则和例子由本 rubric 补充，并在文末“待确认”中列出，由提案作者确认后冻结。

---

## 0. 评判对象与总原则

1. **评判对象**：论文提出或重点评估的 Agent 系统，在论文里**实际尝试并报告了结果**的核心科学问题。引言或展望里的愿景不算。
2. **三轴独立**：O 只看问题本身（从问题陈述读出），V 只看该问题结果的证据，L 只看系统承担了研究流程的哪一部分。一条轴的高低不能推出另一条轴。
3. **取哪个问题**：论文既有基准测试又有开放问题案例时，O 取有具体结果的最高一级；V 取**该问题**结果的证据强度，不取论文中最强的任意一项。
4. **只认书面证据**：判据必须能在 papercard 原文中找到逐字引文（附行号）。笔记写“仍需外部验证/缺少复现”是**缺失**的证据，不能据此提级。
5. **拿不准时**：给出最佳判断，置信度记 low，并标记需全文复核；不新增等级。

## 1. 问题开放度 O（从问题陈述读出）

| 级 | 名称 | 判据（满足即可） | 判断时问 | 典型例子 |
|---|---|---|---|---|
| O1 | 规则世界 | 规则、状态与目标完全给定的封闭环境 | 问题本身是不是一个游戏或纯规则沙盒？ | 棋类、规则明确的玩具环境 |
| O2 | 既定基准 | 事先固定、带参考答案或评分标准的任务集合 | 有没有一个现成的测试集和标准答案？ | QA/考试、benchmark 套件、带答案的复现任务 |
| O3 | 新实例 | 新的问题实例，但答案可由已知方法计算或核对 | 新问题，但答案能不能算出来或查出来？ | 新分子在打分器下的优化、新数据上的分析、基因集功能解释 |
| O4 | 需物理检验 | 产出新的物理对象或实验方案，成立与否最终要靠物理/湿实验检验 | 产出的东西是不是只有做实验才知道行不行？ | 新材料、新合成路线、新蛋白/纳米抗体、新实验条件 |
| O5 | 开放数学 | 答案事先未知、但可被形式化或计算严格检验 | 是不是未解的数学/计算问题，且可被严格检验？ | 未解猜想、组合构造、超越已知最优的算法 |
| O6 | 开放科学 | 关于自然或社会的未知机制/现象，答案事先未知且不能仅靠计算核对 | 是不是在问一个此前没人知道答案的科学问题？ | 新机制、新现象、探索性发现的新反应性 |

**边界规则**

1. 只有“提出假设/想法”而无检验结果：O 按问题本身定级，V 记 V0 或 V1。
2. 回顾性数据上“重新发现”已知结论属 O3，不是 O6。
3. 在**已有**基准上评测记 O2；在固定基准之外的新实例上求解记 O3。
4. 产出是**候选物理对象或实验方案**记 O4，即使论文只做了计算验证（此时 V 记 V2）；产出是答案可计算的预测或分析记 O3。
5. 朝人给定的目标**设计/优化**对象记 O4；**探索性地发现**未知现象或机制记 O6。
6. 只有问题本身是封闭规则世界才记 O1；仿真器若是真实任务的替身（如航天器调度、实验仿真）记 O3。
7. 结论可由数据库或已有知识核对记 O3；O6 要求结论关于未知机制，不能仅靠已有知识核对。
8. O5 包括开放式计算研究：目标是事先未知、可被计算或形式化严格检验的新算法、方法或构造。
9. 基准本身就是贡献的论文通常 O2。

## 2. 验证强度 V（强验证 = V3 或 V4）

| 级 | 名称 | 判据 | 判断时问 |
|---|---|---|---|
| V0 | 声明 | 只有演示、示例、轶事性案例或作者主张，无系统评测 | 除了作者说“能做到”，还有别的证据吗？ |
| V1 | 基准/内部评测 | 基准得分、消融、LLM-as-judge、专家对输出质量打分 | 是不是只在评测集或评分上比高低？ |
| V2 | 计算/仿真/回顾性检验 | 计算验证、仿真、DFT/分子动力学、回顾性真实数据、与文献或数据库已知结论比对、专家对**具体结论**的核对 | 结论有没有被计算或已有数据检验过，但没有新的物理实验？ |
| V3 | 物理实验（强） | 作者完成、**覆盖核心结论**的物理或前瞻实验：湿实验、合成与表征、机器人闭环实验、前瞻性临床、真实部署并测量核心指标 | 有没有真的做实验或部署，并测到了核心结论？ |
| V4 | 证明/复现（强） | 机器可检验的形式化证明（如 Lean 内核检验），或第三方/独立团队/外部实验室复现了核心结论 | 有没有形式化证明，或者别人独立复现了？ |

**边界规则**

1. V3 的实验必须覆盖**核心科学结论**；只证明工具链能跑通的物理演示记 V2（提案§3所说的 V3/V2 边界）。
2. 真实部署或实验确实发生、但证据未报告核心测量结果：记 V2，标需全文复核。
3. 专家只对输出质量打分或给偏好记 V1；专家对具体结论做核对，或回顾性真实案例加确认，记 V2。
4. 按**覆盖核心结论**的最强一项定级，不按最弱项。
5. V4 必须有明确的第三方/独立复现记录，或机器检验的证明；“作者承诺开源”“欢迎复现”不算。

## 3. 系统自主性 L（L0–L3；不代替“解决程度”）

| 级 | 名称 | 判据 | 判断时问 |
|---|---|---|---|
| L0 | 工具 | 模型作为被人调用的工具；人决定每一步 | 每一步是不是都由人决定？ |
| L1 | 任务助手 | 系统执行人委派的单个或若干子任务（检索、写代码、跑分析），研究流程由人决定 | 系统是否只完成交给它的子任务？ |
| L2 | 闭环执行者 | 在人设定的目标内，系统自主完成“计划→执行→观察→修正”的多步闭环 | 系统是否自己迭代闭环，中间无需人介入？ |
| L3 | 自主研究者 | 系统自主决定**研究什么**（提出问题或假设），并自主检验、给出结论；人只做设定或最终审阅 | 研究问题或假设是不是系统自己提出并检验的？ |

**边界规则**

1. 单次执行委派任务，或由人逐步决定下一步，记 L1；系统自己完成多步反馈闭环记 L2。
2. 在人给定的问题或目标内自主迭代（即使生成候选）记 L2；只检验人给定的假设记 L2；自己提出问题或假设并检验记 L3。
3. L 与 V 独立：L3 不意味着结果可靠，L1 也可能有 V3 证据。提案要检验的正是二者的关系。

## 4. 评判流程（每篇必走）

1. 读 papercard 的问题陈述（`最终科学问题`）与“实验与验证”“局限性与风险”。
2. 定 **O**：按 §1 表从高到低问，取第一个“是”；套边界规则；摘一句问题陈述原文作引文。
3. 定 **V**：只看该问题结果；按 §2 表从 V4 往下问，取第一个“是”；套边界规则；摘一句证据原文作引文。
4. 定 **L**：按 §3 表从 L3 往下问，取第一个“是”。
5. 记录：三级代码、各一句中文理由、O 与 V 的逐字引文与笔记行号、是否有争议记录、置信度、是否需全文复核。

## 5. 质量控制

- **逐字引文校验**：每条 O、V 引文必须是笔记第 n 行中逐字存在的一段连续文字；脚本逐条核对，不符即重新编码。
- **双编码一致率**：抽样双编码，报告精确一致率与线性加权 kappa；不一致进入专家复核队列。
- **专家复核队列**：编码者不一致、低置信度、需全文复核、记录有争议的论文，交由领域专家（提案§3：每领域一位，15–20 篇）。
- **不确定性如实标注**：V 是论文**自身报告**的证据强度，不等于独立裁决的“已解决”。

## 6. 待确认（请提案作者确认后冻结）

1. V1/V2 边界：专家核对**具体结论**记 V2、对**输出质量**打分记 V1。
2. L0–L3 的操作定义是否与提案引用的 Wei 等人 L0–L3 一致。
3. 评判对象取“有结果报告的最高开放度问题”，是否符合提案“which specific problem, solved to what degree, on what evidence”的用法。
4. 形式化证明归 V4（依提案“V4 证明/复现”），作者自做物理实验归 V3。
