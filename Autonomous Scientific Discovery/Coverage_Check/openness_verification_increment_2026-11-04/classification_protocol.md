# 662篇核心论文：问题开放度（O）· 验证强度（V）· 系统自主度（A）增量编码规范

日期：2026-11-04（草案，待赵哲确认）。范围：2026-11-01冻结核心清单的662篇唯一工作。三轴定义取自提案《From Computable Tasks to Open Science: A Chronicle of AI Problem Solving》§2(1)；提案只给出两端与少数锚点的地方，本文件补充操作边界，并在“待确认”中列出。此目录为增量分析，不修改主表、Data、Notes、既有审计、正文，不改变科学对象归属、纳入状态或D1–D6机制标签。

## 编码单位

论文提出或重点评估的 Agent 系统，在论文中**实际尝试并报告了结果**的核心科学问题。引言或展望中“可以用于……”的愿景不计。一篇论文若既有基准测试又有开放问题上的案例，O 取有具体结果报告的最高一级，V 取该级问题对应结果的验证强度（不是论文里最强的任意一项）。

## O · 问题开放度（O1–O6）

| 代码 | 名称 | 判据 |
|---|---|---|
| O1 | 封闭规则世界 | 规则、状态与目标完全给定的封闭环境：棋类/游戏、规则明确的仿真沙盒、玩具环境。 |
| O2 | 预定义基准 | 事先固定、带参考答案或评分标准的任务集合：QA/考试、benchmark 套件、论文复现任务、带标准答案的数据分析题。 |
| O3 | 答案可知的新实例 | 新问题实例，但答案可由已知方法计算或核对：新分子/材料的性质预测或在模拟器/打分器下的优化、给定数据集上的新分析、可由已知求解器检验的设计。 |
| O4 | 需物理检验的新对象 | 产生新的物理对象或实验方案，其是否成立只能靠物理/湿实验检验：新合成路线、新材料、新蛋白/纳米抗体、新器件、新实验条件。 |
| O5 | 开放数学/计算问题 | 答案事先未知、但可被形式化或计算严格检验的问题：未解猜想、组合构造、超越已知最优的算法或界。 |
| O6 | 开放科学问题 | 关于自然界或社会的未知机制/现象，答案事先未知且不能仅靠计算核对：新机制、新科学发现、自主提出研究问题并给出经检验的结论。 |

边界：
1. 只有“提出假设/想法”而无检验结果，O 按问题本身定级，V 记 V0 或 V1。
2. 回顾性数据上的“重新发现”已知结论属 O3（答案可知），不是 O6。
3. 物理世界中的执行型任务（如自主选点观测、机器人执行既定实验）：目标由人给定且成功与否可直接核对时属 O3；产生需要实验才能确认的新对象时属 O4。
4. 基准本身就是贡献的论文（benchmark 论文）通常 O2。
5. O2 与 O3：在**已有**基准/测试集（带参考答案）上评测记 O2；在任何固定基准之外的新问题实例上求解记 O3。
6. O3 与 O4：系统产出的是**候选物理对象或实验方案**（材料、分子、反应、合成路线、器件、实验条件），其成立最终需要物理检验时记 O4，即使论文只做了计算验证（此时 V 记 V2）；产出是答案可计算的预测、分析或设计时记 O3。
7. O4 与 O6：朝人给定的目标**设计/优化**对象记 O4；**探索性地发现**此前未知的自然现象、机制或反应性模式记 O6（如机器人探索发现新反应）。
8. O1 与 O3：只有问题本身就是封闭规则世界（棋类、游戏、纯规则沙盒）时记 O1；仿真器若是真实世界任务的替身（航天器调度、实验仿真）记 O3。
9. O3 与 O6：结论可由数据库或已有知识核对（如基因集功能解释）记 O3；O6 要求结论关于未知自然机制、不能仅靠已有知识核对。
10. O5 包括开放式计算研究：目标是事先未知、超越已知最优的新算法/方法/构造（如自动生成并验证新的机器学习研究想法），可由计算或形式化严格检验。

## V · 验证强度（V0–V4）

| 代码 | 名称 | 判据 |
|---|---|---|
| V0 | 仅声称 | 只有演示、示例、轶事性案例或作者主张，无系统评测。 |
| V1 | 基准/内部评测 | 基准得分、消融、LLM-as-judge、专家对输出打分或主观评审；无对真实世界结论的检验。 |
| V2 | 计算/仿真或回顾性检验 | 计算验证、仿真、DFT/分子动力学、回顾性真实数据、与文献或数据库已知结论比对、专家对具体结论的核对。 |
| V3 | 强验证（作者完成） | 机器可检验的形式化证明，或覆盖核心结论的物理/前瞻实验：湿实验、合成与表征、机器人闭环实验、前瞻性临床、真实部署并测量了核心指标。 |
| V4 | 独立复现 | 论文或笔记明确记录第三方/独立团队/外部实验室复现或独立验证了核心结论。 |

边界：
1. V3 的实验必须覆盖**核心科学结论**；只证明工具链能跑通的物理演示不足以成为 V3（记 V2）。这正是提案§3所说的 V3/V2 边界。
2. 笔记中“仍需外部验证/缺少第三方复现”是**缺失**的证据，不能据此给 V4。
3. 按最强且覆盖核心结论的一项定级，不按最弱项。
4. 真实部署或实验**确实发生**但证据包未报告其核心测量结果时，记 V2 并标 `needs_fulltext_review`，不给 V3。
5. 回顾性真实案例加专家对具体结论的确认记 V2；专家只对输出质量打分或偏好评价记 V1。

## A · 系统自主度（A0–A3，对应提案 Wei L0–L3）

| 代码 | 名称 | 判据 |
|---|---|---|
| A0 | 工具 | 模型作为被人调用的工具；人决定每一步。 |
| A1 | 任务助手 | 系统执行人委派的单个或若干子任务（检索、写代码、跑分析），人决定研究流程。 |
| A2 | 闭环执行者 | 在人设定的目标内，系统自主规划并迭代多步实验/计算闭环（如自驱动实验室、BO 闭环、Agent 自主迭代）。 |
| A3 | 自主研究者 | 系统自主提出研究问题或假设，并推动从问题到结论的大部分研究流程，人只做设定或最终审阅。 |

边界：
1. A1 与 A2：系统**自己**完成“计划→执行→观察→修正”的多步反馈闭环、步与步之间无需人介入记 A2；单次执行委派任务，或由人逐步决定下一步记 A1。
2. A2 与 A3：A3 要求系统自己决定**研究什么**（提出问题或假设）并自主检验、给出结论；在人给定的问题或目标内自主迭代（即使生成候选）记 A2；只检验人给定的假设记 A2。

## 证据与输出

每篇记录：`paper_id, openness, openness_rationale_zh, openness_quote, openness_line, verification, verification_rationale_zh, verification_quote, verification_line, autonomy, autonomy_rationale_zh, contested, contested_quote, confidence(high/medium/low), needs_fulltext_review(bool)`。

- 每个 `*_quote` 必须是笔记中第 `*_line` 行（1-based，原笔记行号）里**逐字存在**的片段；主控用脚本逐条核对，不存在即判为无效并重新编码。
- `contested`：仅当笔记明确记录结论被质疑、撤回或反驳时为 true，并给出原句。
- 证据不足时给出最佳判断并降低置信度、标记 `needs_fulltext_review`；不添加新等级。
- 双编码：Sonnet 5.5 为主编码、Haiku 5.5 为独立第二编码；报告两者一致率（加权 kappa），不一致的论文进入专家复核队列（对应提案§3 的领域专家审阅）。

## 待确认（请赵哲确认后冻结）

1. V1 与 V2 的边界：专家对**具体结论**的核对记 V2、对**输出质量**的打分记 V1，是否与提案一致。
2. A0–A3 的操作定义是否与提案引用的 Wei 等人的 L0–L3 一致。
3. 编码单位取“有结果报告的最高开放度问题”，是否符合提案“which specific problem, solved to what degree, on what evidence”的用法。

这是服务于当前综述的操作性编码，不宣称是学界唯一标准；V 是论文自身报告的证据强度，不等于独立裁决的“已解决”。
